## 云服务模型

四张有真实用途的表：`rpg_snapshots`保存完整存档的不可变版本，唯一行ID使同revision并发只能有一个成功；`rpg_proposals`存AI草案；`rpg_feedback`存本人反馈；`rpg_quota_slots`保存独立、不可退款的额度预留。存档按平台注入的访客/登录身份归属，浏览器不能指定用户ID或云数据库连接。

一个 `rpg-service` 云函数处理需要可信身份、确定性规则、原子版本竞争、草案确认和模型密钥的同一业务域。私有表由服务端最小范围访问；每一业务读写仍验证调用者归属。不信任浏览器自填身份或旧Sites请求头。

**新表平台默认 READ=ALL、SUBMIT=ALL、EDIT=CREATOR、DELETE=CREATOR，不足以保护私人存档。** 正式保存真实资料或启用AI前，必须在产品“数据表权限设置”中，将四张表的读、提交、编辑、删除全部限制为应用管理员；公众仅通过带平台身份的云函数访问自己的数据。源Schema/auth文件没有伪造表权限，也不能证明线上权限生效。权限未核对时不配置密钥、不公开使用真实数据。
