## 0. 先看三条硬事实

这三条不是设计，是查证结果，它们决定了下面能怎么设计。

**① 语音输入在生产站能用，在局域网不能用。**
实测同一份代码：

| 环境 | `isSecureContext` | `getUserMedia` | `SpeechRecognition` |
|---|---|---|---|
| `http://192.168.1.5:5174` | false | **undefined** | function |
| `https://life-rpg-world.docileape4.chatgpt.site` | **true** | function | function |

浏览器规定麦克风只在安全上下文给。局域网的 http 地址永远拿不到麦克风，
所以**语音功能没法在"手机连电脑开发服务器"的方式下验证**，只能在生产站或 https 隧道上验。

这也意味着：之前说的"A 方案（adb reverse）"解决不了问题——adb 转发出来的还是 `http://`。
要么用 https 隧道，要么直接在生产站验。

**② 记录官现在没有自己的形象。**
`assistant-scene.tsx` 里用的是 `CharacterPreview`，加载的是 `character-lab/` 里
和你角色**同一套素材**，只是取「性别相反」那一套。也就是说：屏幕上站着的不是你以外的某个人，
是你角色的异性版本。

**已定 2026-10-31：改成卡通树人，不做人形。** 见 §2.1。

**③ 现有模型调用已经一次产出四样东西**（回复 / 记录 / 记忆 / 快捷回复）。
所以"识别情绪处境"不需要多调一次模型，挂在现有契约上就行。但这也意味着
契约每加一个字段，`fitChatTurn` 的 10KB 压缩逻辑就要跟着改——这是个已知的窄口子。

**④ 「情绪变好扣血」原本判不了。**
查证时发现契约里没有任何心情信号，`buildChatContext` 送进去的全是事实
（对话原文、记忆、目标、记录、等级、今日经验），没有感受。让模型判断
"比上次缓了"就是它在猜。
**已定 2026-10-31：加一个心情信号。** 见 §1.4 规则二。

**⑤ `jobless` 这一档是空的。**
存档里没有任何一条记录提到失业/找工作，而且这个 `kind` 从写进类型起
就没有任何东西会填它。
**已定 2026-10-31：砍掉 `jobless`，`kind` 从四档收成三档。**

**⑥ 语音在局域网其实能用，之前说错了。**
浏览器把 `localhost` / `127.0.0.1` 当安全上下文：

| 地址 | `isSecureContext` | `getUserMedia` |
|---|---|---|
| `http://localhost:5174` | **true** | **function** |
| `http://127.0.0.1:5174` | **true** | **function** |
| `http://192.168.1.5:5174` | false | undefined |

所以 `adb reverse tcp:5174 tcp:5174` + 手机访问 `http://localhost:5174`
就能拿到麦克风，不用先去生产站。卡点只剩"本机没装 adb"。

## 1. 情绪怪兽

### 1.1 一句话定义

**怪兽是"你正在扛的某件事"在星球上投下的一块影子。它不会攻击你，你也不需要打卡去打它；
你过日子、说出来、缓过来，它就慢慢薄下去。**

### 1.2 它不是什么（这几条比"是什么"重要）

| 不许做成 | 为什么 |
|---|---|
| 血条 + 攻击按钮 + 数值养成 | 那就是又一个 KPI 面板，正好撞上 spec 的反目标 [已定] |
| 今天没干活 → 怪兽涨血 / 变凶 | "什么都没做但还在撑，不该长得更凶" [已定] |
| 只有"完成任务"才能打它 | "情绪变好和干活一样能打怪" [已定] |
| 三件事全崩的晚上弹出"快打败它！" | "不审判，给台阶 + 主动开正向话题" [已定] |
| 自动生成、塞满星球 | 宠物式收集会把处境娱乐化，让人不想再打开 |
| 全站可见 / 可分享 | 这是你最难的事，不是勋章 |

### 1.3 它从哪来

不在宠物中心，也不在设置里"添加怪兽"。只从一个地方来：**你说的话**。

沿用现有的单次调用：模型在回你的同时，判断这一轮有没有出现"一件正在扛的事"。

**门槛（2026-10-31 已定）**：不要求这件事有名字，要求它**不是**下面三种：

| 排除 | 例子 |
|---|---|
| 不是心情 | "今天有点丧""这周不太顺" → 是情绪，不是处境 |
| 不是单次事件 | 一次考试失利、一次被骂 → 过去了就过去了 |
| 不是自我评价 | "我不行""我很差" → 是评价，不是处境 |

**够格的样子**：一个反复出现的、可以说清是什么的具体事——哪怕是"说不清为什么，就是每天下班回家坐在车里不想上楼"。

为什么放宽到不要名字：难受的事往往恰恰说不清。焦虑到一定程度人是讲不出
"到底怎么了"的。如果只让说得出名字的事变成怪，那说不清楚的痛就永远落不了地，
而它恰恰最需要落地。

防泛滥的办法从"必须有名字"换成**"要你亲手确认"**（见规则一）。
确认这一步本身就挡住了泛滥。

**上限：同时最多 3 只。** 想放第四只，必须先让一只走掉。

### 1.4 三条规则

**规则一 · 出现要你点头**
模型提议"这件事值得放一只怪进来"时，界面不弹窗、不打断，只在对话框下面多一行：

> 要不要把它放进星球？〔放进去〕〔不用，只是聊聊〕

- 选「放进去」→ 怪兽出现，名字模型起，你可以改
- 选「不用」→ 这一轮什么都不发生，那句话照样进记录

为什么问一句：把"要不要给这件事一个形状"的权力留给你。有时候人只是想说说，
不想把这件事变成游戏里的一关。

**规则二 · 挨打是自动的，四种来源一样重**

| 来源 | 判定 | 扣血 |
|---|---|---|
| 说出来 | 这一轮产生了新的 journal 记录 | 10 |
| 做了一件小事 | 一条已达标的 log（不限多大） | 10 |
| 情绪变好 | `mood === 'lighter'`（见下） | 15 |
| 照顾自己 | 睡眠 / 吃饭 / 散步 / 见人这类记录 | 10 |

**心情信号怎么来（2026-10-31 已定加，规则收紧）**

契约新增一个可选字段：

```ts
mood?: 'lighter' | 'same' | 'heavier';   // 缺省按 'same'
```

判定三条铁律：

1. **只和最近 3 轮比，不和"上周"比。** 比得越远越像编的。
2. **拿不准就是 `same`。** 宁可漏判，不许瞎判——误判成 `lighter` 等于白送 15 血。
3. **没有活跃怪兽时这个字段整个不读。** 它只为怪兽服务，不进任何统计。

服务端兜底：`mood` 只在 `state.monsters` 有 `resolvedAt` 为空的条目时才生效；
模型吐了但场上一只怪都没有，直接丢弃。

**为什么这一条值 15 而不是 10**：它是四种来源里唯一"没有实物证据"的，
但也是最难的一种。多给 5 点是为了让"今天心情好了一点"不至于比"今天走了十分钟"还轻。

不设排行榜，不设暴击，不设连击。**四种来源等权**是这条规则的全部重点——
它保证"今天只是睡了个好觉"和"今天干完一个大项目"在怪兽那里是同一件事。

**规则三 · 它不会自己长回来**

- 不做任何事，血量不变。**永远不会因为"没进步"涨血。**
- 只在"出现的那一刻"定一次重量（100 / 200 / 300，按处境轻重），之后这个上限锁死。
- 走到 0 不是"击杀"，是"它薄到看不见了"。留一句你当时说的话作为碑文，收进人生纪念。

### 1.5 数据模型

现有 `Monster` 类型（`lib/game.ts:18`）字段不够用，要加三个：

```ts
type Monster = {
  id: string;
  name: string;
  kind: 'life' | 'setback' | 'emotion';   // jobless 已砍（2026-10-31）
  hp: number;
  maxHp: number;
  createdAt: string;
  // 新增
  sourceRunId: string;   // 哪一轮对话让它出现，方便回溯原文
  hits: { at: string; kind: 'said' | 'acted' | 'felt' | 'cared'; note: string }[];
  resolvedAt?: string;   // 走了
  epitaph?: string;      // 走时留下的那句话
};
```

> **兼容旧存档**：`Monster.kind` 少了一档，但 `normalizeGame` 不校验 `kind`
> （只是 `monsters: value.monsters || []`）。旧存档里如果真有一条 `'jobless'`，
> 界面按 `'life'` 兜底渲染即可，不清空数据——符合 AGENTS.md 第 4 条。

聊天契约加两个可选字段（缺省等于什么都不发生）：

```ts
monster?: {
  event: 'none' | 'appear' | 'wound' | 'vanish';
  kind?: 'life' | 'setback' | 'emotion';
  name?: string;
  weight?: 1 | 2 | 3;
  note?: string;
};
mood?: 'lighter' | 'same' | 'heavier';
```

服务端会做的事（不信任模型）[我提议]：
- `appear` 必须等用户点「放进去」才落库，模型说了不算
- 同一 `runId` 不能重复创建
- 活跃怪兽 ≥3 时拒绝 `appear`
- `vanish` 一律由服务端在 hp 归零时判定，模型无权宣告

**这块会动到 `fitChatTurn`**——它现在按字段优先级压缩到 10KB 以内。
加字段时要同步改，否则极端长度下可能出现"对话存不上"。

### 1.6 界面

**首页：几乎不出现。** 只在陪伴条（那条 80px 的横条）右侧浮一块很淡的暗色，
不点不展开。理由是你反复强调首页要干净，怪兽不该来抢对话的高度。

**世界页：它真正的家。** 星球上盖一块阴影，位置按 `kind` 固定成三块：

| kind | 位置 | 视觉 | 为什么放这儿 |
|---|---|---|---|
| `life`（扛着的生活/身体） | 生命森林 | 灰绿色的雾，树叶垂下来 | 身体和生活的事，长在这片林子里 |
| `setback`（挫折） | 创造之城 | 暗紫色裂痕，从塔尖往下裂 | 你做的事受挫，裂在做事的地方 |
| `emotion`（说不清的情绪） | 星球外缘 | 缓慢旋转的暗环，不落地 | 它不属于任何一块，所以不放在地上 |

这三块的区别不是随机分的：**能指认归属的落在对应领域，指认不了的挂在外缘。**
这直接对应 §1.3 那个门槛——"说不清为什么"的那一类，视觉上也不给它一个确定的位置。

点阴影 → 展开一张卡：名字、它出现那天的你的原话、已经薄了多少、最近挨的几击。
**没有"攻击"按钮。** 只有一句「它还没走」或者「它淡了很多」。

**记录页：** 每只走掉的怪兽，作为一条记录进时间线，带碑文。

### 1.7 已拍板（2026-10-31）

| 项 | 结论 |
|---|---|
| 够重的门槛 | **不看有没有名字**，看它**不是**心情、不是单次事件、不是自我评价。见 §1.3 |
| 出现要不要问 | **要问**。对话框下一行「要不要把它放进星球？」 |
| 世界页位置映射 | **三块**（`jobless` 已砍）。能指认归属的落地，指认不了的挂外缘 |
| 「情绪变好」这条 | **做**，但必须加心情信号，且只和最近 3 轮比。见 §1.4 |
| `jobless` | **砍掉**。零数据，不为它设计 |

## 2. 首页交互与形象

### 2.1 形象：卡通树人（2026-10-31 已定）

**为什么是树人**（不是事后找理由，是这三条真的对得上）：

1. **树有年轮，年轮就是记录。** 你不用跟人解释"记录官为什么是棵树"——它一圈一圈长，本来就在记事。
2. **世界页已经有「生命森林」。** 形象和星球是连着的，不是贴上去的。
3. **树不长手脚，天生绕开"另一个你"。** 它没有性别、不换衣服、不和你的角色撞脸。
4. **树可以"薄下去"。** 这和怪兽的消亡逻辑是同一套语言——都是慢慢淡掉，不是被打死。

**四条硬约束**（照 DeepSeek 那条鱼的原则来）：

| 约束 | 具体 |
|---|---|
| 不做人 | 不长人手人脚、不穿衣服、不站着走路。可以有表情、可以眨眼、可以歪头 |
| 和玩家角色完全脱钩 | 换性别、换时装，记录官不长变。它是它 |
| 只有一个，不做皮肤 | 认得出是因为它始终是那棵树，不是因为有二十套 |
| 配色和紫色主调分开 | 现在主色 `#a98ecf` 紫；记录官用**青绿到暖黄**（`#7fd6b0` → `#e8c07a`），一眼分得出来 |

**状态需求**（光有立绘不够，下面这些必须齐全）：

| 状态 | 什么时候 | 表现 |
|---|---|---|
| `idle` | 平时 | 极慢的呼吸/摇晃，2–4 秒一个循环 |
| `speaking` | TTS 正在读 | 树冠轻轻张开，光从叶缝里透出来 |
| `listening` | 麦克风开着 | 一片叶子竖起，像耳朵 |
| `thinking` | 等模型回复 | 年轮转一圈，很慢 |
| `sleeping` | 减少动态效果开启 | 完全静止，只有极弱的光 |

**尺寸是个硬要求**：同一个素材要在 **56px** 和 **约 400px** 两个尺度上都认得出。
56px 是手机陪伴条里的那个位置（现在那角色就 56px 宽），400px 是桌面版的场景。
这两头差 7 倍，画的时候要按 56px 检查——太细的枝杈到 56px 就糊成一坨了。

**关于让 GPT 出素材**：需求单见 `docs/art/brief-recordkeeper-treant.md`。
但先说死一件事——**AI 出的稿是概念稿，不能直接当素材用**。
`character-lab` 那套是你确认过脸型的（`approved-faces.jpg`），AI 生图会让画风飘，
放在一起像两个游戏。概念稿定方向，落地还要按 `public/art-lab/asset-production-brief.md`
那种格式补一版正式素材（透明通道、多状态、两档尺寸）。

### 2.2 语音

**能做的：**
- 按住说话 → 转成文字填进输入框 → 你确认后再发（不做"说完自动发送"，
  转错一个字就发出去会很烦）
- 它用声音回你（TTS 已经有了，缺一个开关的显眼位置）

**做不到的：**
- **用局域网 IP 打开时完全不可用**（`http://192.168.1.5:5174` 这类，`getUserMedia` 是 undefined）
- 不保证中文识别质量——Web Speech API 走的是浏览器厂商的识别服务，
  荣耀那台机器的百度内核会不会真的调起来，**只有真机点了才知道**

**验证环境（2026-10-31 修正）**：之前误以为"必须部署到生产站"。
实测 `http://localhost:5174` 和 `http://127.0.0.1:5174` **是安全上下文**，
麦克风可用。所以：

```
adb reverse tcp:5174 tcp:5174
→ 手机浏览器打开 http://localhost:5174
→ 麦克风可用，不用先部署
```

卡点只剩"这台机器没装 adb"。装 Android platform-tools 即可，
不需要 https 隧道，也不需要提前上生产。

### 2.3 首页还放得下什么

**先修正一个数**：更早的版本说"还剩 40px"，那是错算——只看了输入框底到
对话卡片底（601→616，中间 15px 其实是卡片内边距），没算卡片底到导航那 3px。

366×694 实测分配：

| 块 | 高度 |
|---|---|
| 顶栏 | 73 |
| 陪伴条 | 80 |
| 对话流 | 353 ← 唯一能伸缩的 |
| 输入框 | 48 |
| 对话卡片下内边距 | 15 |
| 底部导航 | 75 |
| **剩余** | **3** |

**余量是 3px，不是 40px。** 所以首页想加任何新东西，必须从别处砍。

空间不在竖直方向，**在输入框里面**：现在是 `[输入框 222px][8px 间距][发送 74px]`
横向排着。把「发送」改成输入框内右侧的一个圆形箭头按钮，输入框能涨到约 270px，
再塞一个 40px 的麦克风还宽绰。**这是重排，一点不占新高度。**

候选清单：

| 功能 | 放得下吗 | 结论 |
|---|---|---|
| 按住说话（麦克风） | 靠重排输入框，不占高度 | **做** |
| TTS 开关 | 不占高度，放顶栏 | 做 |
| 快捷回复 | 已有，只在它给了建议时出现 | 保持 |
| 今天的记录 | 已有，收起成一行（41px） | 保持 |
| 怪兽的暗影 | 不占高度，浮在陪伴条上 | 做（很淡） |
| 树人的状态动画 | 占陪伴条本身，不额外占地 | 做 |
| 目标进度 / 小行动 | 放不下 | 不放，留在世界页 |
| 今日经验 / 等级 | 放不下 | 不放，留在世界页 |

**备用空间**（真不够时再砍）：

| 砍法 | 省出 | 代价 |
|---|---|---|
| 顶栏 73→56（logo 缩小、藏「私人星球」标签） | +17 | logo 变小 |
| 陪伴条 80→64 | +16 | 树人变小，56px→40px 会糊 |
| 记录条收起成图标 | +27 | 要进去才知道有没有记录 |

三样全砍能省 60px，但都不建议——陪伴条那一刀会直接毁掉树人形象的可辨识度。

### 2.4 已拍板（2026-10-31）

| 项 | 结论 |
|---|---|
| 形象 | **卡通树人**，不做人形。需求单见 `docs/art/brief-recordkeeper-treant.md` |
| 语音验证 | **用 adb reverse + localhost**，不用提前部署 |
| 首页加功能 | 靠重排输入框，不占新高度；余量实为 3px 不是 40px |

**还没定**：首页有没有漏掉你之前提过的功能——想到就说名字。

## 3. 建议顺序

1. **树人形象**（需求单已出，先让 GPT 出概念稿定方向；代码侧先做占位和状态机）
2. **语音**（装 adb → reverse → localhost 验证，和第 1 步可并行）
3. **怪兽**（体量最大，且要挂在世界页和首页，前两步定完才有地方挂）
