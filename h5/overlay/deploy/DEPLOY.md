# One-host deployment handoff

These are preparation templates, not evidence that a server was purchased or deployed. Target: Linux host with Node.js 24, persistent local disk, Caddy and systemd. Substitute the actual host, user, paths, DNS and service binary locations before use. Only one application instance should access this SQLite directory. No model key is included.

1. Confirm hosting account, resource costs, domain ownership, required filing and service scope. Buy or provision only after the owner selects the concrete resource and budget. A personal/non-paying beta does not remove hosting or filing conditions.
2. Create an unprivileged `life-rpg` system account. Place the extracted source at `/opt/life-rpg`; create `/var/lib/life-rpg` owned by that account with mode 0700. Keep the data directory outside the web root. Install the locked dependencies and run the production build as an unprivileged build/deploy account.
3. Create `/etc/life-rpg/runtime.env` from the example. Restrict file ownership/access (for example root:life-rpg, mode0640). Set the real HTTPS `APP_ORIGIN` without a trailing slash; set the persistent absolute data path. Do not put secrets into Git, shell command arguments, screenshots or a public ticket. Keep AI disabled until a credential is explicitly authorized for public use.
4. For CLI operations, run from `/opt/life-rpg` as `life-rpg` with the same environment loaded using Node's `--env-file=/etc/life-rpg/runtime.env`. Run `node --env-file=/etc/life-rpg/runtime.env scripts/manage.mjs init`, then `doctor --production`. Creating accounts uses `invite --out ABSOLUTE_PRIVATE_NEW_FILE`; the destination's parent must already exist and be private. Create separate operator, evaluator and trial accounts; never share a single personal save with the public.
5. Review/install the systemd service and Caddy template. The unit assumes Node is `/usr/bin/node`; change it if different. Point the approved domain to the host and configure HTTPS. The application remains bound to127.0.0.1; the reverse proxy must preserve the browser's Host. Source validation uses the configured origin plus Host, and ignores untrusted forwarded headers.
6. With AI still off, check the public homepage, demo and about; verify anonymous/forged identity requests are rejected, invite login works, and two independent accounts cannot read or delete each other's records/photos/feedback. Confirm logout and account revocation. The repository's HTTP checks are local evidence only, not a replacement for this public deployment check.
7. Configure the authorized production key in the protected environment and set `AI_ENABLED=true`, restart the service, run `doctor --submission`, and use a fictional target to verify generate → edit/confirm → record → cited review → feedback. Keep per-user/site limits small. Monitor the provider's balance and actual bill; request-count limits are not a currency budget cap. Never copy the test-only credential into the public environment.
8. Back up the database consistently using SQLite backup facilities or a planned stopped-service backup, together with the photo directory. Verify restore into another private directory. Configure disk/balance/availability alerts. Do not copy only the main file while WAL writes are active. Retain rollback source and database backup when updating; never rewrite applied migrations.
9. Publish the actual HTTPS URL in the H5 submission document, describe access correctly, and deliver reviewer credentials only through a suitable private submission channel. The fixed demo, README, code ZIP and source repository do not themselves prove the live AI is available. Recheck the current contest form, rights and terms before final submission; preserve the receipt.

Use `doctor --submission` as a configuration gate, not a substitute for network/phone/browser verification. A second real user and an Alipay-browser check are recommended beta checks, not a contest rule confirmed by this template. Conduct them promptly after controlled deployment; paid subscriptions and a mini-program release are outside this first version.
